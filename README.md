# Информационная система онлайн-заказа услуг и товаров «Эстетика & Сервис»

> **Название проекта**: Информационная система онлайн-заказа услуг и товаров «Эстетика & Сервис»  
> **Стек технологий**: React 18 (функциональные компоненты, хуки `useState`, `useEffect`, `useCallback`), Node.js, Express, PostgreSQL 18.  
> **Архитектура**: Клиент-серверное веб-приложение с REST API и реляционной СУБД.

---

## 1. Цель проекта
Разработка веб-приложения для клиентов и администраторов салона услуг с возможностями:
- Просмотра каталога услуг и товаров с фильтрацией и поиском;
- Работы с корзиной покупок, сохраняемой в базе данных PostgreSQL для каждого пользователя;
- Регистрации и авторизации пользователей с разделением ролей (`admin` и `user`);
- Оформления заказа с валидацией адреса и даты доставки (дата не может быть меньше текущей даты);
- Оставления и просмотра отзывов к услугам;
- Управления личным кабинетом (просмотр истории заказов, смена пароля, редактирование профиля);
- Панели администратора с полным CRUD-управлением всеми ресурсами (заказы со статусами и группировкой `x2`/`x3`, услуги, категории, модерация отзывов, пользователи).

---

## 2. Ключевые требования и особенности реализации

### 2.1 Каталог услуг и JOIN-запросы
- Получение списка услуг через API `/api/services`.
- Все данные и связи подтягиваются **исключительно через JOIN-запросы** к таблицам `categories` и `reviews`.
- **Никаких внутренних числовых ID базы данных на фронтенде не отображается**: в интерфейсе выводятся только названия категорий, имена авторов, порядковые номера (№ 1, 2...) и бейджи статусов.
- Доступна фильтрация по категориям, диапазону цен, поиск по названию/описанию и сортировка.

### 2.2 Корзина в базе данных
- Корзина сохраняется на сервере в таблице `cart_items` PostgreSQL с уникальной привязкой к `user_id`.
- При выходе из аккаунта и повторном входе товары корзины сохраняются в базе данных.
- При оформлении заказа корзина конвертируется в заказ в таблицах `orders` и `order_items`.

### 2.3 Оформление заказа и валидация даты
- При оформлении заказа указывается адрес доставки и дата доставки.
- **Валидация даты**: дата не может быть меньше текущей даты (проверяется как на клиенте через `min={today}` и JS-валидацию, так и на сервере в Express).

### 2.4 Отзывы
- Возможность оставить отзыв (рейтинг 1–5 звезд + текстовый комментарий) доступна авторизованным пользователям.
- Все отзывы подтягивают имя автора через SQL `JOIN users u ON r.user_id = u.id`.

### 2.5 Личный кабинет
- Просмотр всех сделанных заказов со статусами («Принят», «В обработке», «Выполнен», «Отменен»).
- Редактирование личных данных (ФИО, email, телефон, адрес доставки по умолчанию).
- Смена пароля с проверкой текущего пароля.

### 2.6 Защита от «глупого» пользователя и сценарий «Забыл пароль»
- Форма восстановления пароля: пользователь вводит email, система подтягивает его секретный контрольный вопрос (например, «Любимый город» или «Кличка питомца»), после чего позволяет безопасно задать новый пароль.
- Валидация всех полей: проверка корректности формата email регулярным выражением, минимальной длины пароля (от 6 символов), длины имени и телефона.

### 2.7 Панель администратора
- Роль `admin` имеет доступ к управлению всеми сущностями:
  - Просмотр всех заказов с группировкой повторяющихся позиций (`Маникюр (x2)`, `Стрижка (x3)`);
  - Смена статусов заказов и удаление;
  - Добавление, редактирование и удаление услуг и категорий;
  - Модерация отзывов;
  - Управление списком пользователей и смена их ролей.

### 2.8 Отказоустойчивость фронтенда при отключении бэкенда
- Фронтенд (порт 3000) и бэкенд (порт 3001) работают независимо.
- При остановке бэкенда (команда `stop`) фронтенд не падает, а выводит дружелюбное сообщение об ошибке с кнопкой «Попробовать снова». При перезапуске бэкенда (`start`) данные восстанавливаются без перезагрузки вкладки.

## 4. Запуск проекта

1. Убедитесь, что запущен PostgreSQL на порту `5432` с БД `clinic_db` (пользователь `postgres`, пароль `123`).
2. В терминале в папке проекта выполните:
```bash
node index.js
```
3. Откройте в браузере:
- **Веб-приложение (Фронтенд)**: `http://localhost:3000`
- **Сервер API (Бэкенд)**: `http://localhost:3001`

### Команды в консоли:
- `stop` — положить сервер бэкенда (для демонстрации обработки ошибок на фронтенде).
- `start` — поднять сервер бэкенда обратно.
- `exit` — корректный выход из программы.
